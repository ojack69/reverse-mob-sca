This tool performs a "black-box" Source Composition Analysis for Android/iOS mobile applications by reversing their components and enumerating their versions. Note: this may introduce some false positives, specially when it's not possible to determine a component version reliably.

- Packaged as a uv project (`uv_build` backend, src layout), exposed as the `reverse-mob-sca` console script (`[project.scripts]` → `reverse_mob_sca.cli:main`) and via `python -m reverse_mob_sca`. Run with `uv run reverse-mob-sca`, install with `pipx install .` / `uv tool install .`.
- Pipeline (`-p android|ios`): obtain component list → validate each entry → (`-t`) expand with child deps → query advisory sources (`-s`, default `sonatype,osv`) → merge into one record per component.
- Modules (`src/reverse_mob_sca/`):
  - `cli.py`: argparse, orchestration, cross-source merge (`build_results`/`merge_vulnerabilities`: components keyed by case-insensitive `(name, version)` via `validate.component_key`; vulns deduped by CVE id or alias overlap; per-vuln `sources`; `dependency_vulnerabilities` rollup).
  - `extract.py` (`-a`): raw `.apk`/`.ipa` or extracted directory, OS-independent (`zipfile`/`plistlib`). Android: `META-INF/<group>_<artifact>.version` (AGP dependency metadata, dominant in modern release APKs) and `META-INF/maven/*/*/pom.properties` (older convention); best-effort, MobSF SBOM via `-f` is the more complete manual fallback. iOS: every embedded `Info.plist` → `CFBundleName@CFBundleShortVersionString@CFBundleIdentifier`.
  - `validate.py`: strict per-platform regexes (`ANDROID_ENTRY_RE`/`IOS_ENTRY_RE`); malformed entries (whitespace, PURL delimiters, ...) are rejected with a warning (source:line) before any network call — deps.dev children go through the same check. Entries are dicts `{line, purl, name, version, bundle_identifier, relation, via}`. Android → `pkg:maven/{group}/{artifact}@{version}`, iOS → `pkg:cocoapods/{name}@{version}`.
  - `depsdev.py` (`-t`, Android): deps.dev v3 `:dependencies` per observed component; children versions are taken **as declared** (user's choice, mvnrepository-like) — may be FPs vs. what actually ships (Gradle conflict resolution, R8); provenance kept in `relation` (`observed`/`direct`/`indirect`) and `via`.
  - `cocoapods.py` (`-t`, iOS): podspec JSON from CocoaPods Trunk CDN (md5-sharded path) at the observed version; root + default subspecs + subspecs requested by parents (fixpoint). Podspecs only have constraints (`~>`, ranges; `satisfies()` implements RubyGems semantics) and `Podfile.lock` isn't shipped, so **observed-only** (user's choice): observed children get `via`/`requirements` and a constraint check (`constraint_violations`); unobserved children become `resolved: False` entries (version None) that are reported but never queried nor recursed. `FRAMEWORK_TO_POD` maps CFBundleName → pod name where they differ.
  - `sources/sonatype.py`: OSS Index `component-report` (50/chunk, 429 retry). Credentials from `SONATYPE_USERNAME`/`SONATYPE_API_KEY` env vars, required only when `sonatype` is selected.
  - `sources/osv.py`: OSV.dev `querybatch` + `vulns/{id}` (Maven data from GHSA); Android only — OSV has no CocoaPods ecosystem, so iOS is Sonatype-only.
  - `severity.py`: CVSS score → label, CVSS v3/v4 vector → score (`cvss` package), GHSA label fallback. `net.py`: shared `requests.Session` honouring `--proxy` (disables TLS verification).
- `--extract-only`: dump the list from `-a` (plus validated resolved children with `-t`; iOS unresolved ones are only logged) to stdout or `-o`, without querying advisory sources.

Historical note: an earlier `android.py` scraped mvnrepository.com HTML pages directly; this was retired after Maven Central/mvnrepository added Cloudflare protection that blocks scraping, and its functionality was folded into the former `main.py` via Sonatype instead. The extraction helpers were later merged into it as well, and `main.py` then became `src/reverse_mob_sca/cli.py` when the project was packaged.
